# Testing

Run the full suite with `npm test` (Vitest, jsdom environment). Every source file has a co-located `*.test.ts`.

## What each layer's tests cover

- **`src/wasm/bridge.test.ts`** — exercises the *real* `character.wasm` module (downloaded via `npm run wasm:download`, not mocked), injecting Node-backed stubs for the fetch effects so it runs without a server. Covers a valid load (name, animations, sprite metadata, state defs), a malformed `.def`, empty `.sff` bytes, repeated calls reusing the same instantiated module, `resolveSprites` (a real decoded sprite, a sprite the sheet doesn't have, and a batched multi-request call), and `loadCmd` (a real `.cmd` file's remap/defaults/command definitions, a malformed `.cmd`, empty input, and reuse alongside `loadCharacter`).
- **`src/wasm/stage-bridge.test.ts`** — the same real-module approach as `bridge.test.ts`, against the real `stage.wasm` (downloaded via `npm run wasm:download:stage`). Covers a valid load (name, stage settings, BG elements, boundaries), a malformed `.def`, an empty `.def` (a valid stage with no `[Info]` section, per the `stage` library's own tolerant parsing), repeated-call reuse, `resolveSprites`, and `resolveAnimationFrames` (a resolved frame at a given elapsed-ticks offset, the blank sentinel for a `null` animation, an empty request list).
- **`src/wasm/engine-bridge.test.ts`** — the same real-module approach, against a locally-built `engine.wasm` (see `docs/architecture.md`'s "Local setup"). Covers starting a match and reading back both fighters' starting animation state, a validation error (an even `bestOf`), ticking (animation time advancing, a state transition once a command matches, a hit reducing health and deciding the round), an unknown match ID, module reuse across repeated `newMatch` calls, and `closeMatch` releasing a session so a later `tick` against it errors.
- **`src/roster/manifest.test.ts`** — the manifest fetch/validation logic in isolation: valid entries, an empty roster, invalid JSON, a missing-field entry, a non-array manifest, and a fetch failure.
- **`src/roster/discovery.test.ts`** — the discovery aggregation logic with a fake `loadCharacter`/`fetchBytes`: a successful entry, a character-load failure, a file-fetch failure, an empty roster, and one failing entry resolving independently of a sibling that succeeds.
- **`src/roster/discovery.smoke.test.ts`** — an end-to-end sanity check wiring `discoverRoster` to the real WASM bridge (not fakes) against real fixture bytes, for both a valid and a broken character in the same run.
- **`src/stage/manifest.test.ts`** — the same coverage shape as `roster/manifest.test.ts`, for the stage manifest.
- **`src/stage/discovery.test.ts`** — the same coverage shape as `roster/discovery.test.ts`, for stage discovery.
- **`src/selection/roster-screen.test.ts`** — the selection screen's rendering and interaction: name/portrait display, the empty-roster message, a non-interactive error card, Continue gated on both picks, independent per-player selection, the mirror-match case (both players picking the same character), and re-rendering replacing rather than appending content.
- **`src/selection/stage-screen.test.ts`** — the stage screen's rendering and interaction: name/portrait display, the empty-list message, a non-interactive error card, the grid's `role="radiogroup"`/`role="radio"` semantics, Continue gated on a selection, single-choice selection (picking a new stage deselects the previous one), re-clicking the selected stage not deselecting it, and re-rendering replacing rather than appending content.
- **`src/setup/setup-screen.test.ts`** — the match setup screen's rendering and interaction: the two option radiogroups each get their own accessible heading, Continue gated on both a round count and a time limit being chosen (independently, regardless of pick order), re-selecting the current round count is a no-op, switching the round count leaves an already-made time limit pick untouched, the exact selected values (including the "unlimited" tag, never a number) are forwarded on Continue, a misconfigured round-count or time-limit option renders a blocking, named error state instead of a default selection, and the Controls section (both players' default keys clearly attributed and never overlapping, all six button names listed, a gamepad/keyboard-fallback note, hidden on the error state).
- **`src/input/key-bindings.test.ts`** — the default keyboard bindings: both players get all four directions and six button names bound to a distinct key, no key is ever shared between the two players, every button name is bound for both, the gamepad button indexes are distinct, and `keyLabel` renders `KeyW`/`ArrowUp`/an unrecognized code correctly.
- **`src/input/keyboard-input.test.ts`** — the live keyboard tracker driven by real `KeyboardEvent`s on `window`: a bound key's direction/button reads held after `keydown` and released after `keyup`, opposing directions held at once are both reported, an unbound key is ignored, every held key clears on `blur`, and no events are reacted to once disposed.
- **`src/input/gamepad-input.test.ts`** — the gamepad poller against fake `Gamepad` objects: no gamepad connected reads as `null` for both players, the first connected pad is assigned to player 1 and its d-pad/buttons read correctly, a second pad is assigned to player 2 (never both to player 1), a disconnected pad's player reads back `null` rather than a stuck button, an assignment-change callback fires on connect/disconnect, and a throwing/missing Gamepad API never crashes the poll.
- **`src/input/tick-input-source.test.ts`** — combining the two trackers: a player with no gamepad reads their keyboard input, a player with a connected gamepad reads that over keyboard, a player falls back to keyboard the read right after their gamepad disconnects, a multi-read burst (simulating several ticks in one frame) stays consistent, `onSourceChange` fires only on an actual change, and `dispose()` releases both trackers.
- **`src/rendering/animation-resolution.test.ts`** — the frame-at-elapsed-time algorithm: walking cumulative per-frame time, a non-positive frame time holding forever, wrapping via `loopStart`, an out-of-range `loopStart` defaulting to 0, and an animation with no frames at all.
- **`src/rendering/match-config.test.ts`** and **`match-config.smoke.test.ts`** — building an `engine` `newMatch` request from loaded character/stage data and each player's own parsed command file: state defs keyed by number (skipping a malformed entry), stage boundary fallback (the stage's own boundaries, half its local coordinate width, or a fixed constant), symmetric starting positions clamped to a narrow stage, a round timer derived from the configured time limit, each player's supplied command file threaded into their own program (never swapped), and falling back to an empty command file per player when none is supplied; the `.smoke.test.ts` drives the assembled request — including a real parsed `.cmd` file and live button input — through the real `character` and `engine` WASM modules together.
- **`src/rendering/scene-composition.test.ts`** — coordinate mapping, facing/frame-flip mirroring, stage layer ordering (behind vs. in front of the characters), and placeholder fallback for a fighter or stage sprite reference with no metadata, or metadata but no decoded pixels.
- **`src/rendering/sprite-pixel-cache.test.ts`** — a sprite is resolved and cached on first request, never re-requested once resolved or once known to have failed, and only genuinely new requests are batched into a call alongside already-known ones.
- **`src/rendering/tick-scheduling.test.ts`** — the fixed-timestep accumulator: zero ticks for less than one interval, one tick with a carried-over remainder, several ticks in one call under the cap, and the cap dropping the rest of a long backlog rather than running it as a catch-up burst.
- **`src/rendering/match-renderer.test.ts`** — the canvas/timer orchestration with every WASM call, draw call, timer, and input source injected as a fake: the loading status shown synchronously, the canvas mounted and the match announced once ready, the initial frame drawn before the tick loop starts, a clear error status instead of a blank screen when the match fails to start, a placeholder draw command instead of a crash when a sprite fails to resolve, the simulation advancing and redrawing once a tick interval elapses, `stop()` cancelling the loop and releasing the session, a stray already-scheduled frame doing nothing after `stop()`, a new call on the same root stopping a previous loop first, each player's own command file threaded into the match request, live input read once per frame and reused across a multi-tick catch-up burst, the input source disposed on `stop()`, and a live status line reflecting each player's active input source.
- **`src/main.test.ts`** — the composition root's wiring, with `loadCharacter`/`loadStage`/`loadCmd`/`renderMatch` and the manifest/byte fetches all injected as fakes: the app shell mounts correctly, the roster renders from a fetched manifest, a manifest failure shows a clear message, picking both players' characters renders the stage screen, a stage manifest failure shows a clear message, picking a stage renders the match setup screen, match rendering starts with both players' loaded characters, the chosen stage, and the configured rounds/time limit once setup's Continue is activated, each player's parsed command file is threaded into match rendering when `loadCmd` succeeds, the match still starts (degrading to no recognized commands) when a `.cmd` file fails to load, and a clear error message instead of a blank screen when a match asset fails to (re)load.
- **`scripts/download-wasm.test.mjs`** — the WASM download script: successful download, output directory creation, a missing version argument, a not-found tag, the all-or-nothing rollback when one of the assets fails partway through, downloading an asset under a different local file name (the `stage`/`engine` targets' `wasm_exec.js` renames), and the CLI's target selection (`character` default, `stage`, `engine`, an unknown target rejected as a usage error).

## Real-WASM fixtures

`src/wasm/testdata/` holds minimal `.air`/`.sff`/`.cns` fixtures (copied from `character-viewer-web`, which itself copied them from the `character` repo's own test data) used by every test that exercises the real WASM module, so expected values come from actually running the module once against them rather than from the same mapping logic under test.

## Real-browser verification

Every layer above is covered by Vitest/jsdom. Both selection screens have additionally been driven in a real headless-Chromium session against the running dev server — jsdom cannot fully substitute for a real browser check on a feature this visual, though no repeatable script for it is checked into this repo yet:
- Backlog item 001 (character roster): roster rendering, independent picks, the mirror-match case, and the Continue confirmation.
- Backlog item 002 (stage selection): stage rendering including a corrupt-stage error card, the radiogroup's single-choice selection, Continue's disabled/enabled states, and the final confirmation naming both players and the chosen stage.
- Backlog item 003 (match setup): both radiogroups' initial/disabled state, Continue staying disabled until both a round count and a time limit are picked, re-selecting the current round count as a no-op, switching the round count without disturbing the time limit pick, and the final confirmation naming both players, the chosen stage, the chosen round count, and the "Unlimited" time limit.
- Backlog item 006 (input handling): the Controls section rendering both players' real default key bindings correctly, the match starting and showing the live "Player 1: Keyboard · Player 2: Keyboard" status, holding a bound key for several seconds with no console errors and no freeze (the canvas keeps updating, the tick loop keeps running).
