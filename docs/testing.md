# Testing

Run the full suite with `npm test` (Vitest, jsdom environment). Every source file has a co-located `*.test.ts`.

## What each layer's tests cover

- **`src/wasm/bridge.test.ts`** — exercises the *real* `character.wasm` module (downloaded via `npm run wasm:download`, not mocked), injecting Node-backed stubs for the fetch effects so it runs without a server. Covers a valid load (name, animations, sprite metadata, state defs), a malformed `.def`, empty `.sff` bytes, repeated calls reusing the same instantiated module, `resolveSprites` (a real decoded sprite, a sprite the sheet doesn't have, and a batched multi-request call), and `loadCmd` (a real `.cmd` file's remap/defaults/command definitions, a malformed `.cmd`, empty input, and reuse alongside `loadCharacter`).
- **`src/wasm/stage-bridge.test.ts`** — the same real-module approach as `bridge.test.ts`, against the real `stage.wasm` (downloaded via `npm run wasm:download:stage`). Covers a valid load (name, stage settings, BG elements, boundaries), a malformed `.def`, an empty `.def` (a valid stage with no `[Info]` section, per the `stage` library's own tolerant parsing), repeated-call reuse, `resolveSprites`, and `resolveAnimationFrames` (a resolved frame at a given elapsed-ticks offset, the blank sentinel for a `null` animation, an empty request list).
- **`src/wasm/engine-bridge.test.ts`** — the same real-module approach, against the real `engine.wasm` (downloaded via `npm run wasm:download:engine`, see `docs/architecture.md`'s "Local setup"). Covers starting a match and reading back both fighters' starting animation state, both fighters' power reset to 0 at match start regardless of the request's own value, a validation error (an even `bestOf`), ticking (animation time advancing, a state transition once a command matches, a hit reducing health and deciding the round), an unknown match ID, module reuse across repeated `newMatch` calls, `closeMatch` releasing a session so a later `tick` against it errors, and (backlog item 007) `resetRound` advancing a decided round to a fresh next round (health/position restored, progress untouched) against the real module, and a typed error for an unknown match ID.
- **`src/roster/manifest.test.ts`** — the manifest fetch/validation logic in isolation: valid entries, an empty roster, invalid JSON, a missing-field entry, a non-array manifest, and a fetch failure.
- **`src/roster/discovery.test.ts`** — the discovery aggregation logic with a fake `loadCharacter`/`fetchBytes`: a successful entry, a character-load failure, a file-fetch failure, an empty roster, and one failing entry resolving independently of a sibling that succeeds.
- **`src/roster/discovery.smoke.test.ts`** — an end-to-end sanity check wiring `discoverRoster` to the real WASM bridge (not fakes) against real fixture bytes, for both a valid and a broken character in the same run.
- **`src/stage/manifest.test.ts`** — the same coverage shape as `roster/manifest.test.ts`, for the stage manifest.
- **`src/stage/discovery.test.ts`** — the same coverage shape as `roster/discovery.test.ts`, for stage discovery.
- **`src/selection/roster-screen.test.ts`** — the selection screen's rendering and interaction: name/portrait display, the empty-roster message, a non-interactive error card, Continue gated on both picks, independent per-player selection, the mirror-match case (both players picking the same character), re-rendering replacing rather than appending content, and (backlog item 009) re-translating the heading/Continue/pick labels, the empty-state message, and an error card's prefix in place on a live locale switch, without losing either player's pick.
- **`src/selection/stage-screen.test.ts`** — the stage screen's rendering and interaction: name/portrait display, the empty-list message, a non-interactive error card, the grid's `role="radiogroup"`/`role="radio"` semantics, Continue gated on a selection, single-choice selection (picking a new stage deselects the previous one), re-clicking the selected stage not deselecting it, re-rendering replacing rather than appending content, and (backlog item 009) re-translating the heading/Continue/select labels, the empty-state message, and an error card's prefix in place on a live locale switch, without losing the current pick.
- **`src/setup/setup-screen.test.ts`** — the match setup screen's rendering and interaction: the three option radiogroups (round count, time limit, and — backlog item 007 — Player 2 Control) each get their own accessible heading, Continue gated on a round count and a time limit being chosen (independently, regardless of pick order; Player 2 Control is pre-selected to Human and never gates Continue), re-selecting the current round count is a no-op, switching the round count leaves an already-made time limit pick untouched, the exact selected values (including the "unlimited" tag, never a number, and the chosen `player2Control`) are forwarded on Continue, a misconfigured round-count or time-limit option renders a blocking, named error state instead of a default selection, the Controls section (both players' default keys clearly attributed and never overlapping, all six button names listed, a gamepad/keyboard-fallback note, hidden on the error state, and — backlog item 007 — swapping player 2's key listing for a "controlled automatically" note once CPU is selected, restoring it if switched back), and (backlog item 009) re-translating every heading/Continue/Controls-section label (but never the physical key/button names) and the blocking error state in place on a live locale switch, without losing the current picks.

## Real-WASM fixtures

`src/wasm/testdata/` holds minimal `.air`/`.sff`/`.cns` fixtures (copied from `character-viewer-web`, which itself copied them from the `character` repo's own test data) used by every test that exercises the real WASM module, so expected values come from actually running the module once against them rather than from the same mapping logic under test.

## Visual regression tests (backlog item 011)

`npm run test:visual` (Playwright, real headless Chromium, not jsdom) guards the roster and stage selection screens against unintended rendering changes — a category of regression the jsdom suite above can't catch, since jsdom never actually paints anything.

- **`tests/visual/roster-stage.visual.spec.ts`** — three committed screenshot baselines: the roster grid with Player 1's character picked, the roster grid with Player 2's character picked, and the stage grid with a stage selected.
- Served through a dedicated `vite.visual.config.ts` (extends the real `vite.config.ts` via `mergeConfig`) whose `publicDir` points at `tests/visual/fixtures/` instead of the real `public/`, since the roster/stage screens fetch a fixed-URL deploy-time manifest that ships empty in the real, committed `public/`. `npm run prepare-visual-fixtures` copies the downloaded `public/wasm/` build into that fixture tree first. See `.vibe/decisions/008-visual-regression-fixture-serving-strategy.md`.
- Extends `web-ui-kit`'s shared Playwright visual-testing preset (`createVisualProjectConfig`), with a stricter diff threshold (`maxDiffPixelRatio: 0.005` vs. the shared default `0.02`) — confirmed by measurement that a single pick-button color regression sits under the shared default even scoped to one card's own screenshot.
- Runs in CI (`.github/workflows/ci.yml`) on every push to `main` and every pull request: lint, then the visual suite only, uploading the diff as a build artifact on failure. The full `npm test` unit/smoke suite is not run in CI yet — CI doesn't currently download the `engine` WASM release several of those tests need, even though `engine` now publishes one (a separate, pre-existing gap, unrelated to the release itself no longer existing).

## Real-browser verification

Every layer above is covered by Vitest/jsdom. Both selection screens have additionally been driven in a real headless-Chromium session against the running dev server — jsdom cannot fully substitute for a real browser check on a feature this visual, though no repeatable script for it is checked into this repo yet:
- Backlog item 001 (character roster): roster rendering, independent picks, the mirror-match case, and the Continue confirmation.
- Backlog item 002 (stage selection): stage rendering including a corrupt-stage error card, the radiogroup's single-choice selection, Continue's disabled/enabled states, and the final confirmation naming both players and the chosen stage.
- Backlog item 003 (match setup): both radiogroups' initial/disabled state, Continue staying disabled until both a round count and a time limit are picked, re-selecting the current round count as a no-op, switching the round count without disturbing the time limit pick, and the final confirmation naming both players, the chosen stage, the chosen round count, and the "Unlimited" time limit.
- Backlog item 006 (input handling): the Controls section rendering both players' real default key bindings correctly, the match starting and showing the live "Player 1: Keyboard · Player 2: Keyboard" status, holding a bound key for several seconds with no console errors and no freeze (the canvas keeps updating, the tick loop keeps running).
- Backlog item 009 (localization): a fresh load with the browser's language forced to English shows the roster screen in English with the locale switcher present; picking Player 1's character, then switching the locale switcher to French live-translates the heading/Continue/pick labels with no page reload while the Player 1 pick (and its "✓") is preserved; a persisted French override in `localStorage` wins over an English browser locale on reload.
- Backlog item 007 (round/match result, CPU opponent): driven against the real `engine`/`character`/`stage` WASM modules through the visual-fixture serving path (`vite.visual.config.ts`), with zero console/page errors observed. Confirmed for real: the Player 2 Control section defaults to Human and toggling to CPU swaps the Controls section to a "controlled automatically" note; a match starts with CPU enabled and the render loop runs continuously (900+ real simulation ticks observed) with the CPU-aware input wrapper active every frame, without any error or freeze. Two pre-existing, out-of-scope limitations were found while attempting to observe a live round ending, and are noted here rather than worked around: (1) `engine`'s `Tick()` never decrements `MatchState.RoundTimer` (confirmed by reading `engine`'s own source — only `match.NewMatchState` ever sets it), so a timeout-based round ending cannot currently happen in a real match at all, only a KO/double-KO can; (2) the visual-regression fixture character's `.cns`/`.cmd` files (authored for parsing tests, not gameplay) define no command that resolves to a working `HitDef` trigger and no velocity response to held movement input, so neither a human nor the CPU opponent can land a hit or visibly move using that fixture. Both are `engine`-repo/fixture-data gaps, not defects in this item's own code — the round/match-end mechanics themselves (mid-burst cutoff, `resetRound`, rematch, back-to-select) are instead verified via the mutation-tested `match-renderer.test.ts` suite above and the real-WASM `resetRound` round-trip in `wasm/engine-bridge.test.ts`.
