# Module: result
**Role:** The round/match result overlay (backlog item 007). `outcome.ts` is pure derivation logic, no DOM/WASM: turns `engine`'s raw round/match outcome codes into a clean "who won" reading — a KO or timeout resolves to the reported winner side, a double KO or a timeout at equal health resolves to a draw, and (defensively) an outcome code or winner side `engine` isn't documented to produce also degrades to a draw rather than throwing or leaving the result undefined — the same "resolve to a clear state instead of crashing" precedent `modules/hud.md`'s `deriveHudViewModel` already set for a malformed WASM payload. `result-screen.ts` builds the overlay once (`createResultOverlay`) and mutates it in place on each show: a round result shows the round winner (or a draw) via a one-shot `aria-live` announcement, plus a separate, non-live countdown that auto-advances after a fixed delay (`onRoundResultDone`) — a round result is not a decision, so no button is asked for; a match result instead shows the overall winner (or a draw) with explicit Rematch/Back to select actions and no countdown. `hide()`/`dispose()` cancel any pending countdown so a stale timer can never fire once the caller has moved on.
**Files:** `src/result/outcome.ts`, `src/result/result-screen.ts`
**Exports:** `OutcomeWinner`, `RoundEndView`, `MatchEndView`, `deriveRoundOutcome(result, round): RoundEndView | null`, `deriveMatchOutcome(matchOver, matchWinner): MatchEndView | null`, `ResultOverlayOptions`, `ResultOverlay`, `DEFAULT_ROUND_RESULT_DELAY_MS`, `createResultOverlay(options): ResultOverlay`
**Depends on:** `modules/i18n.md` (`t`, `onLocaleChange`)
