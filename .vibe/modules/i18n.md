# Module: i18n
**Role:** This app's own localization setup (backlog item 009): wires `web-ui-kit`'s shared i18next integration layer under this app's own namespace (`"mode-quick-versus"`) and its own `localStorage` key (`"mode-quick-versus-locale"`, distinct from `web-ui-kit`'s shared default so a locale choice made here never leaks into another OpenKakutou app deployed on the same GitHub Pages origin). `t(key, defaultValue, vars?)` is what every screen in this app calls to render its own text — it returns the interpolated `defaultValue` verbatim whenever `initAppI18n` hasn't resolved yet in this page (e.g. a test rendering a screen directly), so every call site's fallback text matches its `en.json` entry exactly and the existing test suite keeps asserting plain English text unchanged. `initAppI18n` is only ever called once, from `main.ts`'s real bootstrap, awaited before the very first `renderApp` call.
**Files:** `src/i18n/i18n.ts`, `src/i18n/en.json`, `src/i18n/fr.json`, `src/types/web-ui-kit.d.ts`
**Exports:** `initAppI18n(): Promise<I18nInstance>`, `t(key, defaultValue, vars?): string`, `getI18n()`, `onLocaleChange(callback): () => void`, `NAMESPACE`, `STORAGE_KEY`
**Public contract:** `src/types/web-ui-kit.d.ts` is a scoped ambient `declare module "@openkakutou/web-ui-kit"` — the installed package ships no `.d.ts` of its own, so a named import (`initI18n`, `getI18n`, `WuikLocaleSwitcherElement`, ...) would otherwise fail `tsc` while working fine at runtime/Vitest. Typed only for what this app actually imports by name, not a blanket fallback. See `.vibe/decisions/006-i18n-integration-approach.md` for the full design rationale, including the scope decision that this item covers only the roster/stage/setup screens that exist today (the round/match result screen is a separate, still-`todo` backlog item with nothing yet to extract from).
**Depends on:** none (leaf module; every screen depends on this one, not the reverse)
