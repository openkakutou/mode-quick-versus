# Module: cpu
**Role:** The minimal, first-pass CPU opponent for player 2 (backlog item 007) — intentionally simple, not a full AI. `cpu-controller.ts` is pure and stateless: `decide()` walks toward the opponent when farther than a fixed distance, may attempt an attack once within range (a small per-tick chance, not a held button), and degrades to a fully neutral input on malformed (non-finite) position data — every call is a function of that call's own observation only, nothing persisted, so there is nothing to reset when a round ends or a match restarts. It mutates a caller-supplied `RawPlayerInput` in place rather than allocating a fresh one each tick, the same allocation discipline `modules/input.md`'s own trackers already follow. `cpu-input-source.ts` composes this with the existing input-source abstraction instead of bypassing it: `createCpuAwareInputSource` wraps a real `TickInputSource`, leaves player 1's read exactly as the base source produced it, and overwrites player 2's in place using the controller's decision — fed a live fighter-position snapshot via a closure the caller supplies at construction time (reading `modules/rendering.md`'s own already-existing per-frame state), rather than adding a parameter to `TickInputSource.read()` itself. This keeps every input source (`keyboard`, `gamepad`, human-combined, CPU-wrapped) satisfying the exact same interface. See `.vibe/decisions/010-round-match-result-and-cpu-opponent-design.md`.
