# Module: audio
**Role:** Match audio (backlog item 013): a stage's background music on loop for the whole match, and each fighter's decoded sound effects played the instant `engine` reports them triggered. `pcm-conversion.ts` is pure: deinterleaves and normalizes a character's decoded, interleaved signed-16-bit PCM (`wasm/types.ts`'s `Sound.pcm`) into one `Float32Array` per channel scaled to `[-1, 1]`, clamping an out-of-range sample instead of overflowing, and degrading a non-positive channel count to mono rather than dividing by zero. `sound-lookup.ts` is pure: builds a `(group, sample)`-keyed lookup (`buildSoundLookup`) of a character's own decoded sounds once per match — the same "resolve once, reuse it" convention `rendering/match-renderer.ts`'s own `buildSpriteMetaByKey` already uses for sprites — and resolves a triggered `SoundEvent` against it (`findSound`), returning `undefined` for a legitimate miss (a character with no sound file, or a triggered group/sample the character has no matching decoded sound for) rather than an error. `match-audio.ts` is the actual `AudioContext` driver, built with the same "every external effect is an injectable parameter with a real default" convention as every other real-effect module in this app: `playMusic(bytes)` decodes a stage's music file once (async, via `decodeAudioData`) and loops it via a single `AudioBufferSourceNode`, replacing any music already playing; `playSound(sound)` builds a real `AudioBuffer` from the decoded PCM once per distinct `Sound` (keyed by object identity in a `WeakMap`, mirroring `sprite-pixel-cache.ts`'s own "decode once, cache by identity" pattern) and plays it immediately via a fresh, lightweight source node reusing that cached buffer — never rebuilding it on a later play of the same sound. A fixed cap (`MAX_CONCURRENT_VOICES = 16`) bounds how many one-shot sources can be playing at once; a trigger past the cap is dropped silently rather than growing the audio graph unbounded, which a worst-case multi-tick catch-up burst (several fighters, several `PlaySnd` events each) could otherwise do in a single rendered frame. The whole controller degrades to a silent no-op — never throwing, never rejecting `playMusic`'s promise — when `AudioContext` itself can't be constructed (an unsupported environment), when a music file is undecodable, or when a sound has no PCM to play, matching this app's existing "degrade, don't crash or stall the match" convention (`.vibe/decisions/004`). A `visibilitychange` listener resumes a suspended `AudioContext` once the tab becomes visible again (some browsers auto-suspend a backgrounded tab's audio context); no explicit "don't pile up on refocus" logic is needed beyond this, since a dropped simulation tick's own `PlaySnd` events are already never received by `rendering.md`'s own tick-scheduling cap. `stop()` stops the music and every active one-shot, closes the context, removes the visibility listener, and is idempotent.
**Files:** `src/audio/pcm-conversion.ts`, `src/audio/sound-lookup.ts`, `src/audio/match-audio.ts`
**Exports:** `buildPlanarChannels(pcm, channels): Float32Array<ArrayBuffer>[]`, `buildSoundLookup(character): Map<string, Sound>`, `findSound(lookup, event): Sound | undefined`, `createMatchAudio(options?): MatchAudio`, `MatchAudio` (`playMusic(bytes): Promise<void>`, `playSound(sound): void`, `stop(): void`), `MatchAudioOptions`
**Depends on:** `modules/wasm.md` (`Sound`/`SoundGroup` from the character bridge, `SoundEvent` from the engine bridge — types only, no runtime call)
