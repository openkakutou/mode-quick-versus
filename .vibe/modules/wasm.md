# Module: wasm
**Role:** One bridge per WASM dependency, each its own Go program with its own runtime instance: `bridge.ts` bridges to the `character` WASM module, `stage-bridge.ts` bridges to the `stage` WASM module, `engine-bridge.ts` bridges to the `engine` WASM module (combat simulation). All expose a typed loader/caller returning either the result or a descriptive error, never throwing — including a failed runtime instantiation itself (a missing/version-mismatched `.wasm`/`wasm_exec.js` asset, or a `WebAssembly.instantiate` rejection), caught internally by each bridge's own `ensureGoRuntimeReadyOrError` wrapper (backlog item 008) rather than left to reject the caller's promise. `bridge.ts`/`stage-bridge.ts` additionally expose batched `resolveSprites()` (decoded pixel data for a set of sprite references); `stage-bridge.ts` also exposes `resolveAnimationFrames()` (which sprite an animated BG element currently shows) and, on `loadStage()`'s response, a stage's background music file path (backlog item 013, empty when the `.def` declares no `[Music]` section); `bridge.ts` also exposes `loadCmd()`, parsing a character's `.cmd` input command file independently of `load()` (a `.cmd` file stands alone — no `.def`/`.air`/`.sff`/`.cns` bytes needed), and `load()` itself takes an optional 5th `sndBytes` argument (backlog item 013) decoding a character's `.snd` sound file into `CharacterSummary.sounds` — omitted or `null`, exactly like an absent `SoundFile`, means "no sound data," not an error. `engine-bridge.ts` differs in call shape: every exposed function takes/returns one JSON-encoded request/response rather than typed arguments, so it also owns the JSON encode/decode at the boundary; it exposes `newMatch`/`tick`/`closeMatch` plus (backlog item 007) `resetRound` — advancing a decided round to a fresh next round (health/position restored, the next round number computed by the session itself; `Progress` untouched) — once round-transition flow was actually needed, see `.vibe/decisions/010`. `tick()`'s response also now reports each fighter's own `PlaySnd` sound events triggered that exact tick (backlog item 013, `TickResponseData.sounds`) — a discrete per-tick event log, never accumulated across ticks.
**Files:** `src/wasm/bridge.ts`, `src/wasm/types.ts`, `src/wasm/stage-bridge.ts`, `src/wasm/stage-types.ts`, `src/wasm/engine-bridge.ts`, `src/wasm/engine-types.ts`
**Exports:** `loadCharacter(defBytes, airBytes, sffBytes, cnsBytes, sndBytes?, options?): Promise<CharacterResult>`, `loadCmd(cmdBytes, options?): Promise<CommandFileResult>`, `resolveSprites(sffBytes, requests, overrideBytes?, options?): Promise<SpritePixelResult[]>`, `resetWasmBridgeForTests(): void`, `WasmBridgeOptions`, `CharacterSummary` (incl. `sounds: SoundGroup[]`), `CharacterResult`, `Sound`, `SoundGroup`, `CommandFile`, `CommandFileResult`, `loadStage(defBytes, options?): Promise<StageResult>`, `resolveSprites` (stage), `resolveAnimationFrames(requests, options?): Promise<{ok, sprites}|{ok, error}>`, `resetStageWasmBridgeForTests(): void`, `StageWasmBridgeOptions`, `StageSummary` (incl. `musicFile: string`), `StageResult`, `newMatch(request, options?): Promise<EngineResult<NewMatchResponseData>>`, `tick(request, options?): Promise<EngineResult<TickResponseData>>` (`TickResponseData.sounds: [SoundEvent[], SoundEvent[]]`), `resetRound(request, options?): Promise<EngineResult<ResetRoundResponseData>>`, `closeMatch(matchId, options?): Promise<EngineResult<{}>>`, `resetEngineWasmBridgeForTests(): void`, `EngineWasmBridgeOptions`, `SoundEvent`
**Depends on:** (none — talks directly to the `character`/`stage`/`engine` WASM modules)
