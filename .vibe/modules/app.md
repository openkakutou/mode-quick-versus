# Module: app
**Role:** Composition root. Builds the `web-ui-kit` app shell — including a `<wuik-locale-switcher>` in the toolbar (backlog item 009) — discovers the character roster and mounts the character selection screen, then — once both players continue — discovers the stage list and mounts the stage selection screen, then — once a stage is chosen — mounts the match setup screen, then — once setup is confirmed — re-fetches and re-loads both players' character files (including each one's own `.cmd` input command file) and the chosen stage's file (discovery itself never retains raw bytes/full data, only the name) and starts match rendering. A fetch/load failure at that point degrades to a clear, translated error message, same handling used at every earlier screen boundary — except a `.cmd` file's own fetch/parse failure, which degrades only that one fighter to no recognized commands rather than blocking the match. The real bootstrap (`mount()`, module-scope) awaits `initAppI18n()` before the first `renderApp` call, so the very first paint already has the right language; `renderApp` itself stays synchronous-callable so tests can call it directly without bootstrapping i18n. The toolbar's own locale-change subscription only retranslates the locale switcher's accessible label — the brand title/version are untranslated proper nouns, and each screen's own text is retranslated by that screen itself (see `modules/i18n.md`, `modules/selection.md`, `modules/setup.md`).
**Files:** `src/main.ts`, `src/version.ts`
**Exports:** `appVersion: string`, `renderApp(root, version, options?): Promise<void>`
