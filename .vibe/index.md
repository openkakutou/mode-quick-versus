## Observed patterns
- TypeScript with `strict`, `noUnusedLocals`, `noUnusedParameters` enabled (`tsconfig.json`)
- Explicit `.ts` extensions on relative imports (`allowImportingTsExtensions`)
- Test files co-located with source as `*.test.ts`/`*.test.mjs`, using Vitest + jsdom
- Every external effect (`fetch`, WASM instantiation) is injected as a parameter with a real default, so every layer is testable under jsdom without a running server — same shape from `wasm/bridge.ts`/`wasm/stage-bridge.ts` down through `roster/manifest.ts`/`stage/manifest.ts`, `roster/discovery.ts`/`stage/discovery.ts`, and `main.ts`'s own `renderApp`
- The DOM-building logic of a screen is a pure exported function (`renderApp(root, version, options?)`, `renderRosterScreen(root, entries, options)`, `renderStageScreen(root, entries, options)`) taking its target element and data/callbacks as parameters, replacing the target's previous content on each call rather than appending
- Dev-tooling scripts outside the app bundle live in `scripts/` as plain `.mjs`, not bundled/type-checked by `tsc`
- Fixture-driven tests that exercise a real WASM module use minimal real fixture files (character `.air`/`.sff`/`.cns` copied from `character-viewer-web`'s own test data; the real `stage.wasm`/`stage-wasm_exec.js`, downloaded the same way as `character.wasm`) rather than depending on a sibling checkout at test time
- A result that can fail in an expected way (a WASM load, a manifest fetch, a file fetch) returns a discriminated-union/typed result instead of throwing, so a UI layer can show a clear error state instead of crashing
- One bridge file per WASM dependency rather than a shared/generalized loader — each is an independently released, independently versioned Go program; `wasm/stage-bridge.ts` even keeps its own `wasm_exec.js` on disk (`stage-wasm_exec.js`) rather than reusing `character`'s copy, so the two can never silently drift out of pairing
- A single-choice grid (one shared pick, e.g. the stage screen) uses `role="radiogroup"`/`role="radio"`/`aria-checked` and never toggles back to "no selection" on a re-click; an independent-pick grid (one pick per player, e.g. the roster screen) uses plain toggle buttons with `aria-pressed`, since either player's slot can legitimately be empty
