## Observed patterns
- TypeScript with `strict`, `noUnusedLocals`, `noUnusedParameters` enabled (`tsconfig.json`)
- Explicit `.ts` extensions on relative imports (`allowImportingTsExtensions`)
- Test files co-located with source as `*.test.ts`/`*.test.mjs`, using Vitest + jsdom
- Every external effect (`fetch`, WASM instantiation) is injected as a parameter with a real default, so every layer is testable under jsdom without a running server — same shape from `wasm/bridge.ts` down through `roster/manifest.ts`, `roster/discovery.ts`, and `main.ts`'s own `renderApp`
- The DOM-building logic of a screen is a pure exported function (`renderApp(root, version, options?)`, `renderRosterScreen(root, entries, options)`) taking its target element and data/callbacks as parameters, replacing the target's previous content on each call rather than appending
- Dev-tooling scripts outside the app bundle live in `scripts/` as plain `.mjs`, not bundled/type-checked by `tsc`
- Fixture-driven tests that exercise the real WASM module use minimal `.air`/`.sff`/`.cns` fixtures copied from `character-viewer-web`'s own test data rather than depending on a sibling checkout at test time
- A result that can fail in an expected way (a WASM load, a manifest fetch, a file fetch) returns a discriminated-union/typed result instead of throwing, so a UI layer can show a clear error state instead of crashing
