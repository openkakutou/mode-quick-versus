# Match audio: ship the web (Web Audio API) target only, no in-app mute control this cycle

**Context:** Backlog item 013 asks for match audio on both the web build (Web Audio API) and the native Windows/Mac/Linux/Android build (SDL2_mixer), per roadmap `.vibe/decisions/026`. This repo has no native codebase at all yet — only the `go-gl`/SDL2 vs. Ebiten benchmark spike under `benchmarks/render-lang-spike/`, not an actual application. The execution environment also still lacks the native toolchain entirely: no `pkg-config`, no SDL2 development headers, no display server (`$DISPLAY`/`$WAYLAND_DISPLAY` both empty) — the exact same gap `.vibe/decisions/011` already documented and deferred for backlog item 008's release packaging. Separately, consulting the UI/UX expert during planning raised whether a basic in-app mute/volume control belongs in this item's own scope, since the acceptance criteria only ask for audio to play and degrade gracefully, and this app has no settings/options screen or volume control of any kind today.

**Decision:**
1. Implement and verify only the web audio target this cycle: a stage's background music decoded and looped via the Web Audio API, and every `PlaySnd` event `engine` reports per tick played from that fighter's own decoded `character` sound data, both verified for real in a browser (a live match run end-to-end with a real `.snd` fixture triggering on every tick, plus an undecodable music file and a mid-match tab-visibility toggle, all confirmed not to crash, stall, or log an error). The native SDL2_mixer half is left entirely unattempted — there is no native application in this repo to add it to, not just a missing library. The backlog item stays `status: blocked` (not closed) with a `## Blocked` section naming this precise gap, the same pattern `.vibe/decisions/011`/backlog item 008 already established.
2. No in-app mute or volume control is added this cycle. The acceptance criteria for this item name only playback and graceful degradation, not a control surface; adding one would mean designing a settings/options screen that doesn't exist yet and that no other acceptance criterion calls for.

**Reason:** Re-attempting the native target without a working `go-gl`+SDL2 toolchain or a display server would repeat exactly the unverifiable, non-reproducible situation `.vibe/decisions/011` already rejected once for this same environment — a "pass" that proves nothing. Shipping the fully-verifiable web half now, honestly marked incomplete, is strictly better than leaving both halves undone. Deferring the mute control keeps this item scoped to what its own acceptance criteria ask for, consistent with the autonomous workflow's "oversized scope" gate (implement what's asked, flag an addition rather than silently inventing it).

**Rejected alternatives:**
- *Write the native Go/SDL2_mixer code anyway, unverified* — rejected: this project's workflow is TDD-first with mandatory runtime verification before a task can be marked complete; code that can neither compile nor run in any available environment cannot pass through that loop honestly, the same reasoning `.vibe/decisions/011` already applied.
- *Hand-extract SDL2 headers/`pkg-config` from downloaded `.deb` packages without root* — rejected for the same reason `.vibe/decisions/011` rejected it for backlog item 008: technically possible but produces an unverifiable, ABI-risky environment nothing else (CI, a real release) would ever match.
- *Add a basic mute toggle to this item's own scope* — rejected: no acceptance criterion asks for it, and this app has no settings surface to hang it on yet; deciding one now would mean designing UI beyond this item's stated mandate, the same reasoning `.vibe/decisions/007`/`006` already used to defer a not-yet-built screen's concerns.
- *Split "web audio" and "native audio" into two separate backlog items now* — rejected: the autonomous workflow's oversized-scope gate reserves a split for a genuine Product Owner decision; implemented as one item instead, with the incomplete half flagged via the `## Blocked` section, mirroring backlog item 008's own precedent exactly.
